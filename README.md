# ML Text Classifier API

A small, end-to-end machine-learning service that classifies customer
support tickets into four categories — **billing, technical, account,
shipping** — built with **scikit-learn** (TF-IDF + Logistic Regression)
and served with **FastAPI**.

By Maruthi Pawan Avula.

## What this demonstrates

- A complete ML lifecycle in one repo: data generation → training →
  evaluation → model artifact → HTTP inference → tests → Docker image.
- A clean separation between training code (`src/`), inference helpers
  (`src/predict.py`), and the web layer (`app/`).
- Honest evaluation: the numbers below come from an actual run of the
  code in this repo (see *Evaluation* for important caveats).

## Architecture

```
 data/tickets.csv          src/train.py               models/
 (synthetic dataset) ────▶ TF-IDF + Logistic ──────▶ model.joblib
                           Regression pipeline        metrics.json
                                                            │
                                                            ▼
                            app/main.py (FastAPI)     src/predict.py
   POST /predict  ────────▶ load artifact once, ─────▶ category +
   GET  /health             validate, delegate         confidence
```

## Dataset — synthetic, by design

`data/tickets.csv` contains **480 synthetic tickets** (120 per category),
generated by `src/data.py` from hand-written templates with randomized
slot values (amounts, order numbers, dates, places). **No real customer
data is used.** The generator is deterministic (`seed=42`), so the CSV in
the repo is exactly reproducible:

```bash
python -m src.data   # rewrites data/tickets.csv
```

## Evaluation (actual run)

Training script: stratified 80/20 split (`random_state=42`).

```
Dataset: 480 rows (384 train / 96 test)
Test accuracy: 1.0000

              precision    recall  f1-score   support
     account       1.00      1.00      1.00        24
     billing       1.00      1.00      1.00        24
    shipping       1.00      1.00      1.00        24
   technical       1.00      1.00      1.00        24
```

**Read this honestly:** a perfect score is expected here, and it does
*not* mean the model would score 1.00 in production. The synthetic
tickets are generated from templates, so each category has clean,
distinctive vocabulary and the classes are almost linearly separable.
Real tickets are messier — overlapping wording, multiple issues per
ticket, typos — and would score lower. The point of this project is the
pipeline and the engineering around it, not the headline number.
The test suite additionally checks hand-written example tickets (not
produced by the templates) for every category.

## Run it

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt        # runtime deps
pip install -r requirements-dev.txt    # + pytest / httpx for tests

python -m src.train                    # trains, prints report, saves models/
uvicorn app.main:app --port 8000       # serves the API
pytest                                 # 7 tests
```

### Sample requests

```bash
curl localhost:8000/health
# {"status":"ok","model_loaded":true,"categories":["account","billing","shipping","technical"]}

curl -X POST localhost:8000/predict -H 'Content-Type: application/json' \
  -d '{"text":"Hi, my package was marked delivered but nothing arrived at my door"}'
# {"category":"shipping","confidence":0.8684,
#  "probabilities":{"shipping":0.8684,"billing":0.0735,"account":0.0339,"technical":0.0242}}
```

`/predict` returns `503` with a clear message if the model artifact
hasn't been trained yet; the artifact location can be overridden with
the `MODEL_PATH` environment variable.

## Docker

```bash
docker build -t ticket-classifier .
docker run -p 8000:8000 ticket-classifier
```

The image trains the model during the build, so the container starts
with a ready artifact.

## Project layout

```
app/main.py         FastAPI app: /health, /predict
src/data.py         synthetic dataset generator (templates + slots)
src/train.py        training + evaluation, saves model & metrics
src/predict.py      model loading + prediction helpers
data/tickets.csv    bundled synthetic dataset (480 rows)
tests/              training smoke tests + API tests (TestClient)
models/             trained artifacts (git-ignored, regenerated by train)
```

## Verification status

Actually executed in the build environment (Python 3.12, scikit-learn
1.9.x, FastAPI 0.143.x): dataset generation, full training run (output
above), all 7 pytest tests passing, and a live `uvicorn` boot checked
with `curl` against `/health` and `/predict`. The Dockerfile is written
to standard practice but was **not** built in the build environment (no
Docker daemon available there); its steps mirror the verified local
commands exactly.
